# Транслятор конфигурационного языка — вариант №2

Консольная программа переводит учебный конфигурационный язык в JSON.
Синтаксический анализ выполняется библиотекой **Lark** по отдельной грамматике
`src/grammar.lark`; регулярные выражения и ручной разбор строк вместо
специализированного парсера не используются.

## Требования варианта

- входной текст читается из файла, заданного аргументом командной строки;
- JSON записывается в файл, заданный аргументом командной строки;
- числа имеют формат `0[oO][0-7]+`;
- массивы записываются в круглых скобках, элементы разделяются запятыми;
- имена соответствуют `[_A-Z][_a-zA-Z0-9]*`;
- значение — число, массив или постфиксное выражение;
- константы объявляются конструкцией `имя is значение;`;
- выражения записываются как `@{...}` и поддерживают `+`, `-` и `min()`.

Вариант не задает синтаксис словарей, строк или комментариев, поэтому
транслятор их не добавляет. Документ состоит из набора объявлений констант.
Каждое объявление становится полем выходного JSON-объекта: имя константы —
ключ, вычисленное значение — значение поля. Это выбранная интерпретация
структуры результата: в тексте варианта формат верхнего уровня JSON отдельно
не уточнен, поэтому его стоит согласовать с преподавателем.

## Синтаксис и семантика

```text
документ       ::= объявление*
объявление     ::= ИМЯ "is" значение ";"
значение       ::= ЧИСЛО | массив | выражение
массив         ::= "(" значение ("," значение)* ")"
выражение      ::= "@{" элемент_постфиксной_записи+ "}"
элемент        ::= ИМЯ | ЧИСЛО | "+" | "-" | "min()"
ЧИСЛО         ::= 0[oO][0-7]+
ИМЯ           ::= [_A-Z][_a-zA-Z0-9]*
```

Числовые литералы интерпретируются как восьмеричные и в JSON выводятся как
обычные десятичные числа. Например, `0o10` преобразуется в `8`.

В примере постфиксной формы в задании приведен литерал `1`, хотя регулярное
выражение чисел задает только восьмеричную запись `0[oO][0-7]+`. Реализация
следует формальному правилу чисел: вместо `1` используется `0o1`.

Постфиксное выражение вычисляется стековым алгоритмом. `+`, `-` и `min()`
являются бинарными операциями: два операнда записываются перед оператором.
Например, `@{BASE 0o2 +}` означает `BASE + 2`, а
`@{0o7 0o3 min()}` возвращает `3`. Выражение должно оставить в стеке ровно
одно значение. `min()` и арифметические операции принимают только числа.

Константы вычисляются в порядке объявления. Можно ссылаться только на
константы, объявленные ранее. Повторные объявления и ссылки на неизвестные
константы приводят к диагностике. Константа может содержать число, массив или
вычисляемое выражение. Ссылка на константу в исходном значении записывается
внутри выражения, например `@{VALUES}`.

В соответствии с формой массива в задании пустой массив не поддерживается.
Пробелы и переводы строк между элементами синтаксиса игнорируются. Запятые в
массивах обязательны; завершающая запятая не допускается.

## Установка

Требуется Python 3.10 или новее.

```bash
python -m venv .venv
```

Linux/macOS:

```bash
. .venv/bin/activate
python -m pip install -e ".[test]"
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
```

## Запуск

```bash
./run.sh --input examples/network.conf --output output.json
```

Альтернативный запуск:

```bash
python -m src.main -i examples/network.conf -o output.json
```

Windows:

```bat
run.bat --input examples\network.conf --output output.json
```

Параметры `--input` (`-i`) и `--output` (`-o`) обязательны. При ошибке
чтения/записи, синтаксической ошибке или ошибке вычисления программа выводит
сообщение в `stderr` и возвращает ненулевой код завершения.

## Примеры конфигураций

В языке варианта №2 нет словарей или именованных полей, поэтому примеры
используют вложенные массивы. Порядок элементов описан ниже.

### 1. Сетевой сервис — `examples/network.conf`

```text
HTTP_PORT is 0o1750;
RETRY_LIMIT is 0o3;
TIMEOUT_SECONDS is 0o12;
```

Ожидаемый JSON:

```json
{
  "HTTP_PORT": 1000,
  "RETRY_LIMIT": 3,
  "TIMEOUT_SECONDS": 10
}
```

### 2. Учебный курс — `examples/education.conf`

```text
LESSON_COUNT is 0o10;
PRACTICE_COUNT is 0o4;
TOTAL_ACTIVITIES is @{LESSON_COUNT PRACTICE_COUNT +};
```

Ожидаемый JSON: `{"LESSON_COUNT": 8, "PRACTICE_COUNT": 4,
"TOTAL_ACTIVITIES": 12}`.

### 3. Складской учет — `examples/warehouse.conf`

```text
START_STOCK is 0o120;
INCOMING is 0o20;
OUTGOING is 0o7;
CURRENT_STOCK is @{START_STOCK INCOMING + OUTGOING -};
LOW_STOCK_LIMIT is @{START_STOCK INCOMING min()};
```

Ожидаемый JSON содержит исходные значения и вычисленные поля:
`START_STOCK: 80`, `INCOMING: 16`, `OUTGOING: 7`,
`CURRENT_STOCK: 89`, `LOW_STOCK_LIMIT: 16`.

## Тестирование

```bash
python -m pytest -v
```

Тесты проверяют восьмеричные числа, массивы и их вложенность, объявления и
ссылки на константы, каждую операцию, выражения внутри массивов, запуск CLI,
а также синтаксические и семантические ошибки.

## Замечания для публикации в Git

Файлы `README.md`, `.gitignore`, `src/`, `tests/` и скрипты запуска включены.
Для истории разработки используйте отдельные коммиты в стиле
Conventional Commits, например:

```bash
git init
git add README.md .gitignore pyproject.toml run.sh run.bat
git commit -m "chore: add project structure and documentation"
git add src/
git commit -m "feat(parser): implement variant 2 grammar and AST"
git add tests/ examples/
git commit -m "test: cover parser, evaluator and sample configurations"
```

После создания публичного репозитория добавьте его как `origin` и отправьте
ветку `main` на выбранный Git-сервис. Публичную публикацию и отправку в СДО
нужно выполнить из своей учетной записи.

Пример публикации после создания пустого репозитория на Git-сервисе:

```bash
git remote add origin <URL-публичного-репозитория>
git push -u origin main
```
